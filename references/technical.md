# 技术分享模式

目标是让听众能解释方法、判断证据并继续讨论。视觉上保持简洁，内容上保留必要条件，不把技术讲解缩成口号。

## 候选风格

- 首选建议：Berkeley CS285。白底黑字、少装饰、解释图占据主要空间；标题提出当页要解释的问题；推导、直观例子和实验结果交替出现。已看过的样例页码见 [索引](catalog.md)。这是推荐，尚不是用户确认的模板。
- Stanford CS348K：黑白强标题、较多留白，适合视频世界模型概念介绍和讨论。中文通常使用正常宽度的黑体，不照搬英文压缩字体。
- LeCun Harvard：适合架构对照和逐步展开。借鉴模块、箭头、颜色一致性，避免无必要地继承顶部彩纹、机构徽标和作者身份。

## 内容组织

根据任务选用：任务与问题、直觉、方法结构、关键机制、实验与对比、局限和讨论。不是必须凑齐的固定章节。

- 算法页先建立输入、输出和中间状态，再给关键公式。公式旁解释新符号、优化对象和假设；长推导进附录。
- 架构图同一模块跨页使用同色、同名、同方向。清楚区分训练和推理、数据采集和模型想象、观测和潜状态。
- 结果页先展示能支撑结论的图，再给简短解释。保留数据集、指标方向、基线、预算与统计范围；缺失条件写明，不能补编。
- 消融页说明改变了什么、其他条件是否保持一致。综述中的不同论文若实验条件不同，不画成可以直接排名的柱状图。
- 工程实现保留真正影响使用的复杂度、时延、硬件、接口和失败案例；与演示目的无关的代码细节放附录。
- 所有“最新”“领先”等时间敏感表述在制作时重新查证。样例中的旧结论只作为当时的观点。

## 页面起点

16:9。初始建议：标题 32–36 pt，正文 22–26 pt，公式 24–30 pt，图注 14–16 pt。根据投影环境、用户模板与语言调整，先删减或拆页再缩小字体。中文段落一般不超过 3–5 行，长表移到附录。

| 页面 | 布局 | 适用内容 |
| --- | --- | --- |
| 开场 | 简短标题、讲者、日期，保留大块留白 | 明确主题与范围 |
| 方法解释 | 主要区域为结构图，旁边少量标注 | 架构、状态流、数据流 |
| 单点推导 | 上部公式，中部图解，下部一句解释 | 损失、状态更新、规划 |
| 对比 | 两侧同尺度、同标注体系 | 训练/推理、方法差异 |
| 结果 | 单个大图和一段有限结论 | 性能、泛化、效率 |
| 讨论 | 已知限制、待解问题 | 不确定性、下一步 |

设计参数见 [design-presets.json](design-presets.json) 的 `technical`。颜色是新设计建议，不能当作来源课件的精确色值。
