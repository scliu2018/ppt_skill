# 非技术分享模式

目标是让听众理解问题、方案价值、证据和接下来要做的决定。精美来自视觉层级、留白、真实场景与一致的品牌，而不是更多装饰。

## 场景分支

- 融资：问题/机会、产品如何解决、为什么可信、业务模式、进展、团队、里程碑、融资用途。只按现有材料展开；没有客户、收入或测试结果时明确缺项，不能补成漂亮数字。
- 非技术科普：熟悉的场景、简短类比、核心机制、现实案例、能力边界。不要硬加市场和融资章节。
- 客户或产业交流：业务痛点、方案工作方式、部署与集成、效果证据、使用条件和下一步。

## 用户样例提炼

本地样例 A 是深蓝/黑色背景、蓝青光效、场景/概念主视觉和大数字构成的融资风格；样例 B 使用科技感封面、白底内容、蓝青强调、实物图片与技术方案图。原件及具体页码保存在 `.local/REVIEW.md` 和 `.local/user-references.json`。这里只记录可迁移的视觉方法。

- 融资主风格可以采用 A 的深色科技视觉；数据密集页使用干净、统一的底色，避免复杂背景影响阅读。
- B 更接近产品/技术方案介绍。可以借鉴真实场景、架构和结果的组合，但面向非技术听众时减少段落、解释缩写，并把推导移到附录。
- 不混用两个品牌的徽标、公司名称或未获授权的商业素材。参考中的实验数值、市场规模、融资额和预测不作为默认填充值。

## 页面与讲法

标题说清楚当页主题或有证据的结论。将技术特征连接到具体使用效果，但不要把“可能改善”改成“已经证实”。

| 页面 | 主视觉 | 信息重点 |
| --- | --- | --- |
| 封面 | 一张有留白的主视觉 | 项目名称和一句清楚的定位 |
| 问题 | 真实业务场景或简洁对比 | 谁遇到什么问题、代价是什么 |
| 解决方案 | 一幅易懂的过程/产品图 | 输入、作用过程和可见结果 |
| 证据 | 一个主要指标或清晰实验图 | 条件、基线、范围和来源 |
| 产品/落地 | 实物、界面或案例 | 谁使用、怎样交付 |
| 商业/融资 | 简洁原生图表和必要数字 | 实际与预测分开、资金对应里程碑 |
| 收束 | 产品/场景图或干净背景 | 已经证明什么、具体希望达成什么 |

初始建议：封面 44–52 pt、内容标题 32–38 pt、正文 24–28 pt。主视觉和关键证据优先，页面常见 1 个主点、2–3 个支持信息，按内容调整。避免整套演示都变成卡片墙。

数字要标明单位、时间、统计口径。市场规模、预测与客户数据缺来源时保留为待核实内容，不生成假图表。融资方案由用户材料决定，这个模式不替用户决定估值或投资结论。

设计参数见 [design-presets.json](design-presets.json) 的 `nontechnical`；`light_content` 可用于白底产品/技术页。参数是原创起点，不是原 PDF 的精确复刻。
